# 0.3.0 feature tour recording notes

Recorded 2026-09-30 against `main` after the mount feature landed: the 0.3.0 app plus drag-to-select, the scan table's stored-login status and **Mount on this computer**. It replaces the first cut recorded earlier the same day, which had no mount chapter. Every shot is the real app driven by Playwright at human pace; nothing is mocked in the page. The edit plan is `docs/video/tour-0.3.0.json`; the lab and pipeline are in `scripts/video/` (see `docs/video/README.md`).

## Recording environment

This cut was recorded in a disposable Linux container, not on SmartNAS or a production network. The storage it shows is a local lab built by `scripts/video/demo_lab.sh`:

- **Network shares:** three Samba servers bound to loopback aliases on 192.168.50.0/24. `studio-nas.lan` (NetBIOS STUDIO-NAS) and `reception-pc.lan` have DNS names from `/etc/hosts`; BACKUP-BOX has only a NetBIOS name, to show how the scan table handles missing DNS. The scan, SMB sign-in, share listing, reads, writes and copies in the film are real SMB traffic to these servers.
- **Cloud:** "Studio S3" is a local S3-compatible test server (moto) reached through rclone, added in the GUI with disposable keys. The provider list is shown; other providers were not connected.
- **VM storage:** libvirt's test driver with a fictional `vm-images` pool and three volumes. No hypervisor or VM disk is involved.
- **Files:** a fictional studio's files generated by `scripts/video/demo_lab_files.py`.
- **NFS:** not filmed. The container has no NFS server; NFS appears only as a connection type.
- **Mounts:** the service ran with `--allow-mounts --mount-folder /home/morgan/remotefs`, using rclone 1.60 and FUSE (`fuse3`) in the container. The NAS folder and the S3 bucket were mounted for real; the terminal commands ran against those mounts, and the copied 96 MB file and edited `brief.md` were read back over SMB in the browser. Windows and macOS mounts were not filmed. Windows per-account drives have not yet been run on a real Windows computer.

Demo passwords are disposable and appear only as masked fields or through `--password-stdin`. The host has no real credentials.

## What each chapter exercises

1. Sign-in and the sidebar.
2. Finder-style selection: tick, Shift-click range, ⌘-click add/remove, rubber-band drag-select, the right-click menu, Get Info, ⌘A, filter and sort, and the ⌘/ shortcut list.
3. New folder from the right-click menu, ⌘C/⌘V copy into it, rename, and editing and saving a Markdown file.
4. Network scan of 192.168.50.0/24 (the wait is sped up 3×), mapping STUDIO-NAS with saved credentials, browsing a share and previewing a file.
5. The host right-click menu, unmounting (disconnecting) the server, remapping with the stored login, and mapping a second server.
6. Starring a folder, shortlisting from the right-click menu, reloading the page, and reopening an SMB folder from the shortlist.
7. Adding the S3 connection (form entry sped up in the edit), copying a local folder into the bucket, opening files there, and copying from S3 onto the NAS.
8. Mount on this computer: mounting a NAS folder read-write and the S3 connection read-only from the right-click menu, using both from a terminal (a 96 MB copy onto the NAS mount, a text append, and `rm` refused with "Read-only file system" on the S3 mount), waiting for uploads (sped up 3×), checking the results in the browser and ejecting both. The terminal uses `du -h` rather than `ls -l`: with rclone 1.60, `ls -l` on a FUSE mount prints an "Input/output error" for extended attributes even though the file is fine.
9. A multipart ZIP of 114 MB with 40 MB parts on the server's staging folder, producing three ready parts.
10. Libvirt pool and volume inventory.
11. The `remotefs` CLI against the same service: login, scan, credentials, shares, connect, ls, get, a local-to-NAS copy, remotes, a ZIP job and saved locations. Each command was typed on screen and executed in a real bash session; the output shown is its actual output.
12. `examples/embed`: the README templates assembled into a small job-tracker app, started from the terminal, with the picker choosing a folder and returning a credential-free descriptor.

Parts of chapters 11 and 12 are played back faster than they were recorded (1.35× and 1.2×); see the edit plan.
